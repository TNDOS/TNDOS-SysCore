# 架构决定（2026-10-18，作者裁定）

这四条覆盖了上一份 ARCH-REVIEW.md 里的五个岔路口。**已决，不再讨论。**

## 决定一 彻底抛弃 EFI 驱动模型

> 「彻底抛弃 EFI 驱动模型，需要的情况下交给 EFI 加载。」

**含义**：`src/drv/vga.c` / `kbd.c` 这种"我们自己写 .EFI 驱动 + LoadImage"的模型**取消**。

**后果**：
```
· src/drv/ 整目录退役
· efidos.sys 里的 DEVICE=VGA.EFI / config.sys 里的 DEVICE=KBD.EFI 删掉
· 内核里那条 LoadImage 分支**保留**，但降级为"万一需要，让固件去加载"的兜底，
  不再是我们要维护的第二套驱动框架
```

理由很硬：.EFI 驱动的代码在固件内存里，**ExitBootServices 之后必然失效** ——
它天生达不到这个项目的目标。

## 决定二 驱动"先装进内存，用不用以后再说"

> 「在接手前用 EFI 加载好 TNX 驱动到内存，运不运行无所谓，只要在内存，他就可以使用。」

**这是最有分量的一条，它改变了驱动的生命周期模型。**

现在的 TNX 驱动在 `attach` 里就把硬件初始化做完了（改 8042、复位 NVMe 控制器、
pci_disown……）—— 而 `attach` 发生在 **ExitBootServices 之前**。这会造成：
```
· 提前碰固件还在用的硬件 -> 固件在收尾时卡死（PS/2 那次实测过）
· 提前 disown PCI 设备 -> 固件和驱动抢同一个控制器
```

**新模型：两段式**
```
load   （退出前）  把 TNX 映像读进内存、校验、注册进驱动表
                    **一根手指都不碰硬件**
start  （退出后）  真正初始化硬件、注册块设备/输入后端
                    **这时固件已经不管事了，抢也没人抢**
```

PS/2 驱动已经是这个形状了（懒初始化 8042）—— **把它变成规矩，推广到所有驱动**。
NVMe / AHCI 现在是在 attach 里做初始化，要拆成两段。

**API 影响**：`TND_DRIVER_DESC` 需要一个 `Start` 回调（v2.8）。

## 决定三 接管是目标，但没开发好就不提前退出

> 「不管怎么说都得接管，但是没开发好那就没必要提前 exitboot（现阶段是测试 exit 后有没有模块可以顶上）。」

**含义**：
```
· EXITBOOT 保持为一条**测试命令**，不是启动流程的一部分
· config.sys / autoexec.bat 里**不自动**调它
· 现阶段的验收标准就是：exit 之后，块设备/输入/控制台/文件系统有没有人顶上
```

这条其实是在说：**别为了"能 exit"而 exit**。接管不完整的时候提前退出，
只会让机器变成一块砖，而拿不到任何有用信息。

## 决定四 复用的是"怎么运行"，不是照搬模型

> 「复用的是咋运行的，不是模型复用、代码直接复用，得看人家咋实现的。」

**含义**：搬别人的东西之前，先看懂它**为什么那样工作**。
照搬代码但不懂机制，等于把别人的假设嫁接进我们的环境 —— 出问题查不了。

**具体到 FatFs**：
```
· 看 diskio 的接口设计（为什么是这五个函数、每个的语义边界在哪）
· 看 ff.c 怎么处理 FAT32 的根目录簇链、BPB 字段
· **可以复用代码**（wheel 就是 wheel），但要能解释它每一步在干什么
· 不能因为"FatFs 这么做"就假设我们的 blk 层语义和它匹配 ——
  比如字节序、扇区对齐、错误码、多扇区读的原子性，都得自己对一遍
```

## 落地顺序

```
1  TND_DRIVER_DESC 加 Start 回调（v2.8），PS2 改成"load 空 / start 初始化"
2  NVMe / AHCI 拆成两段：load 只读映像，start 才 reset + 建队列 + 注册块设备
3  src/drv/ 退役，配置里去掉 DEVICE=VGA.EFI / KBD.EFI
4  FatFs 接进构建（先修 Build-Pe 把 clang stderr 打出来）
5  mkfat 支持 FAT32 -> QEMU 复现真机 -> 真机验证
```

**第 1 条做完，"提前碰硬件"这一整类问题就消失了** —— 包括今天卡住的那些。
