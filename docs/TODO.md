# 已知问题与后续  > 本文件从 README.md 拆出。最后更新随源码走。 
## 已知问题 / 待办

- **IDT 只接管了四个向量**：`src/kernel/trap.c` 用 `sidt` 抄下固件整张 IDT，
  只替换 #DE/#UD/#GP/#PF 四个入口 —— **异常能说话了**（打向量号 + 出错码 + RIP + CR2 然后停机）。
  **中断仍然全部归固件**，所以定时器 / USB / 磁盘的中断还在固件手里，
  处理器仍然是轮询的。整张 IDT 要等 `ExitBootServices` 那一刻做一次性切换。
- **没有虚拟内存 / 分页**：目前是 UEFI 建立的身份映射。
- **Shell 仍编译在 kernel.efi 内**：按方案最终要分离成独立用户程序。
- **没有 Syscall / 用户态 / 调度器**。
- ~~**驱动模型还很薄**~~ —— **这条已过时**。现在有完整的一套（见 `docs/DRIVER-SDK.md`）：
  TNX 驱动格式（基址 0x2000000，不走固件 `LoadImage`）、驱动表 / 注册 / 绑定实例、
  内核与驱动之间的 `TND_API_TABLE`（v2.5），以及诊断接口。
  **还没做的**是驱动之间互相要服务。
- **驱动映像缓冲不释放**：每个驱动几十 KB，故意留着最保险。
- **驱动必须是单个 TNX**：不支持依赖库，也没有导入表。
- **`REN` 是复制后删源**（UEFI 没有 rename），受 64 KB 缓冲限制。
- **`COPY` 不支持目标为目录**，需要写全文件名。
- **PMM 空闲查找是 O(n) 线性扫描**，页多了会慢；够用但迟早要换成空闲链。
- **本地化尚未做**：控制台是纯 ASCII（见上面「控制台字符集」一节），中文界面要等字体层。

## 后续（按方案）

**SP3 的具体排期见 [SP3-PLAN.md](SP3-PLAN.md)** —— 每个驱动走到第几步、剩下的活怎么排、

## 待修的 bug：空闲一会儿会自己重启

**症状**：摆在提示符那儿不动，过一阵机器自己重启。
**不是崩溃** —— 崩溃会挂住或者三重异常，重启是另一回事。

**判断**：UEFI 固件默认开着一个**看门狗定时器**（一般 5 分钟左右）。
不关它、也不喂它，到点就复位。

**为什么必然发生**：普通 EFI 程序跑几秒就退出，碰不到它；
**我们长期挂在 Boot Services 底下**（shell 停在提示符等输入），
所以看门狗一定会在某个时刻咬上来 —— 这不是偶发，是早晚。

**修法**：

```c
gBS->SetWatchdogTimer(0, 0, 0, NULL);   /* 放在很前面，在耗时的初始化之前 */
```

**验证**：进系统后什么都不干，放 10 分钟。
