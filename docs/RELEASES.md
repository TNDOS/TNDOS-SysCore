## 发行格式

**从 0.3.2-M4-SP2.5 开始，至具备 ISO 构建能力之前，不再以 `.img` 发行成品，改为 VHD。**

```
成品名    TNDDOS-<version>-x86_64.vhd
内容      GPT + ESP(FAT) + TNDDOS 引导器 + 内核，和以前一模一样
用法      Windows 双击挂载/卸载；QEMU 用 -drive file=...vhd 直接引导
```

裸 `.img` 在 Windows 上要额外的挂载工具，而 VHD 是系统自带就能处理的格式。

**改回去的条件**：等有了 ISO 构建能力（El Torito + 我们自己的引导链），
发行物就应该是 ISO。届时三档格式分工：

```
ISO                   通用发行物 —— 刻盘、虚拟机、Ventoy 都能直接吃
多分区磁盘镜像 .img     Linux / BSD 系下便捷使用 —— 分区表和引导项由我们写好
VHD                    Windows 下便捷使用 —— 双击挂载，不需要额外工具
```

在 ISO 可用之前，三者里只能交付 VHD（`.img` 退而不发）。

## 约定

```
tag 里带 "-" 的   ->  **预发布**（v0.3.2-M4-SP2、Pre-1 这种）
干净的 v0.3.2      ->  正式版
```

这是 `.github/workflows/release.yml` 自动判定的 —— **tag 一推，Release 就出来了**，
预发布标记也是自动的，不用手点。

**注意**：GitHub 是从 **tag 指向的那个提交**里读工作流的。所以
**工作流文件必须先提交、再打 tag** —— 指向更早提交的 tag 永远触发不了它。
`TNDOS-SDK` / `TNDOS-ToolsKit` / `TNDOS-SysAPP` 三个仓库的 `v1.0` 至今没有 Release，
就是因为那些 tag 指向的是加工作流之前的提交。
