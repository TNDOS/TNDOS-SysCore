## 0.3.3 —— 真机护栏 + VFAT

### 前置：真机护栏（必须在动文件系统之前做完）

0.3.1-M3 已经上过真机。当时安全，但**是运气**：kernel.efi 距 64 KB 上限只剩 12.8 KB。
而那次的 TNX 窗口预留（`pmm_reserve`）一度是**静默失效**的 —— 那是直接往物理地址写内存。

三件事：

1. **把写盘自检从默认 autoexec.bat 里拿出来**，改成单独的 selftest.bat。
   默认启动链全程只读。（现在每次开机都会在真实 ESP 上 md TMP / copy / del / rd）
2. **识别真机并明确警告**。OVMF 会自报家门（FirmwareVendor 含 "EDK II"），
   真机是 AMI / Insyde / Phoenix。真机上打横幅，并让 SAFE ON 能屏蔽所有写命令。
3. **pmm_reserve 加断言**：AllocatePages 失败就拒绝加载 TNX 程序，
   而不是默默往里写。

### 主线：VFAT / 长文件名

**先纠正一个前提：VFAT 不是取代 8.3，是叠在它上面。**

每个长名文件都必须有一个自动生成的 8.3 短名（LONGFI~1.TXT）——
LFN 条目的校验和就是从那个短名算出来的。所以"不再支持 8.3"字面上做不到。
正确的目标是：**不再要求用户用 8.3；长名在所有地方默认工作。**

**内核 · 读**
- t_u16_to_utf8() —— lib/utf8.c 现在只有反向的
- vfs.c:258（& 0xFF 硬截断）和 api.c:316（非 ASCII 变 ?）两处换成正确转换
- 去掉无脑 t_toupper —— 长名大小写敏感，只有短名才转大写
- TND_NAME_MAX 64 → 256（长名上限 255 个 UTF-16 码元）
- DIR 的列对齐重做 —— 长名会撑破现在的固定宽度排版

**内核 · 写**
- 基本免费：写还是走 UEFI 的 FAT 驱动，EDK2 自己生成短名 + LFN 条目
- 但要在 vfs_create 上验一遍（超长名 + 非 ASCII）

**工具（真正要写代码的地方）**
- mkfat.ps1 生成 LFN 条目：属性 0x0F、13 码元一组、短名校验和、~1 名字生成算法
- **做完之后我们自己造的盘才有长名** —— 这是现在测不出 LFN bug 的根源
  （我们的盘全是 8.3，问题永远不暴露）

**通配符**
- 现在的 * / ? 假设 8.3。VFAT 下 * 的语义有坑（DOS 的 *.TXT 在长名上行为特殊），
  要单独定义并写进文档

**验证**
- 造一个盘塞满：中文名、超长名、混合大小写、多个同类文件触发 ~1 ~2 ~3、只有扩展名超长的
- 然后 DIR / TREE / FIND / ATTRIB / COPY / EDIT 逐个过一遍

## 0.3.4 —— 定时器子系统

ticks() 现在老实返回 0。做掉它一次性解锁三样：

- **光标闪烁**（DOS 那种下划线 / Ins 后整块。UEFI 不给改形状，
  所以形状要自己画，而闪烁需要时钟）
- DATE / TIME
- EDIT 能显示"已保存 2 秒前"这类反馈

需要：PIT/APIC + 中断处理 + 重进入保护。**不是编辑器的功能，是时钟中断的功能。**

## 0.4.0 —— FAT 驱动链（VFS 换底）

**这是一个完整里程碑，体量比 0.3.2 整版都大。**

```
1. 块设备层（先走 UEFI EFI_BLOCK_IO_PROTOCOL，将来换自有 NVMe/AHCI）
2. BPB 解析 -> 判定 FAT12/16/32
3. FAT 表读写 + 簇链遍历
4. 目录项：8.3 读写 -> LFN 读 -> LFN 写
5. 跨簇文件读写
6. VFS 双轨换底（可切回 UEFI SFS 对照 —— 那是现成的回归测试）
```

**为什么必须做**：ExitBootServices 之后 UEFI 的 FAT 驱动会跟着 Boot Services 一起消失。
**没有自己的 FAT 驱动，就别想离开 UEFI。** 它同时是 M4 的真正前置。

顺带：FAT12 表项那个"3 字节装 2 项"的编码是全项目最恶心的格式细节之一，
做完之后磁盘工具才有得写。

## 0.4.x —— 磁盘工具

FORMAT / CHKDSK / SCANDISK / LABEL / diskpart（复刻 Windows 界面）

**强制规则：默认 dry-run。**

列出打算写哪些扇区、什么结构，加 /apply 或 commit 才真写。

DOS 的 FDISK 以"手滑一下盘就没了"著称 —— 那是**包袱**，
而本项目的原则就是"保留交互模型，丢掉包袱"。

被砍掉的（记录一下为什么）：DEFRAG（没有真实场景）、JOIN（是 VFS 特性不是工具）、
MODE / KEYB / NLSFUNC（是驱动或 NLS 层，不是独立命令）。

## 0.5.0 —— M4 驱动模型 + TAKEOVER

分两半，处境完全不同：

| | 前置 | 能做吗 |
|---|---|---|
| **框架**（协议契约、GUID 注册、服务路由） | 无 | 随时能做 |
| **实体**（驱动真硬件） | 卡在 ExitBootServices ← 卡在自有 IDT ← 卡在自有 FAT 驱动 | 要等 0.4.0 |

### ExitBootServices 的设计（已定）

**配置项只声明意图，不执行切换。**

```
config.sys:   TAKEOVER=ON        <- 只声明

启动链走到"驱动就绪"检查点：
   自有控制台 / 键盘 / 块设备 + FAT 都就绪 -> 切
   有缺的                                  -> 不切，打印缺什么，继续以 UEFI 模式跑
```

再加一个手动入口 TAKEOVER，开发时可以"先以 UEFI 模式干活、想切的时候再切"。

**两个必须记住的坑：**
- **MapKey 会失效**：GetMemoryMap 之后只要分配了任何东西，ExitBootServices 就会失败。
  必须"取图 -> 立刻 Exit，失败 -> 重取 -> 再 Exit"
- **framebuffer 信息要在 Exit 之前缓存**：EFI_GRAPHICS_OUTPUT_PROTOCOL 是 Boot Services，
  Exit 之后就访问不到了，但帧缓冲内存本身还在

**顺序不能反**：ExitBootServices 不是"一个开关加一段初始化"，是**"自给自足的那一刻"**。

### 交棒用例（保留）

TAKEOVER=OFF（默认）时 Boot Services 还活着，可以：

```
C:\>CHAIN \EFI\ubuntu\grubx64.efi
```

**TNDDOS 在成为"真操作系统"之前就已经有用了** —— 一个能读盘、能跑工具、能改文件、
然后交棒给别的引导器的系统。这条建议尽早单独做掉，成本几十行。

## 更远 / Later

- **DEBUG** —— 难的不是读内存，是反汇编器。而 TNX 有个明确的反目标：**没有符号表**。
  所以只能是地址级的，体验比 DOS 的 DEBUG 还糙。**单项最大的工程。**
- **NLSFUNC 那个位置** —— 国家信息 + 代码页 + 字体。
  那是**中文本地化**的正确落点（不是当初以为的"一个独立命令"）。
- **自有 NVMe / AHCI 驱动** —— 0.4.0 的块设备层最后要换掉的那个东西。
