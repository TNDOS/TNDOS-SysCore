# 回顾与驱动最小集合

写于 2026-10-18。这一份是给下一阶段定方向的，不是进度报告。

## 一 从哪来，到哪了

**目标从第一天起没变过**：不是把传统 DOS 搬到 UEFI，是**重做一个 UEFI 时代的 DOS** ——
保留交互模型，丢掉内存模型。

已交付：M0 / M2 / M3 / TNX v1.0 / v1.1 / M4(SP0–SP2) / SP3。

**这一阶段（ExitBootServices 接管）真正做成的：**

```
✓ ExitBootServices 真的过了 —— QEMU 上全链跑通
✓ 交还 Boot Services 之后仍然是活的：
    控制台   fb 后端，直接写帧缓冲
    输入     PS/2，退出后才初始化 8042（配置字节 0x77 -> 0x44）
    时基     TSC
    内存分配 自己的堆（接管表里 AllocatePool/FreePool/Stall 换成我们的）
    文件系统 NVMe -> blk -> FAT16 -> 目录项
✓ 多驱动并存（每个驱动一个窗口槽，同槽查重）
✓ AHCI 和 NVMe 都注册块设备
✓ 串口在退出后不再走固件协议
✓ 滚屏：开机自动 WC + movnti 非临时存储
```

**这一阶段暴露、但还没解决的：**

```
✗ 真机上第 5 次文件打开开始全失败
    efidos.sys ✓ VGA ✓ PS2 ✓ NVME ✓ | AHCI ✗ config.sys ✗ autoexec.bat ✗
    形状是"资源用完"，不是路径也不是 FAT
✗ 只认 FAT16（真机 ESP 是 FAT32）
✗ cd / type 被 vfs_resolve 挡住（因为 VFS 还挂在固件上）
✗ 构建不是原子的（先清空再重建，中途失败留半成品 —— 咬过两次）
✗ 两套驱动模型并存（src/drv 的 .EFI 与 SDK 的 TNX）
```

**这一阶段最重要的一条方法论**（比任何一个 bug 都值钱）：

> 要观测，又不能改变被测对象。
> EDK2 的 MapKey 每次内存图变动就自增，而 `log_puts` 走固件 SerialIo 协议**会分配内存** ——
> 在 GetMemoryMap 和 ExitBootServices 之间打印，key 立刻失效。
> 换成 `con_puts`（fb 后端，只画像素不分配）打 `A B C D` 标记，一次就定位。
> **"看起来卡住"的地方，先找一个不产生副作用的观测手段，再动代码。**

## 二 一条被推翻的假设（必须记下来）

**曾经认定：真机是 Intel VMD / RST 硬阵列，NVMe 被藏在 VMD 后面，所以扫不到。**

为此加了 VMD 支持（class 0x0104 + VMCAP 总线范围）和 PCI 桥跟随（0x19 secondary bus）。

**2026-10-18 查实：错。** 机器上是：

```
Standard NVM Express Controller  PCI\VEN_144D&DEV_A80D  inf=stornvme.inf
```

三星 NVMe，微软**原生**驱动，**没有 VMD**。所以：

- VMD 代码**留着**（它是对的，对别的机器有用），但**不是**这个问题的答案
- PCI 桥跟随也留着（同理）
- **真正要查的是：bus 0 上那块 0x0108 为什么没被认出来**

这比 VMD 好查得多 —— 因为 Windows 用原生驱动就能看见它，说明它就在 bus 0 上。

## 三 驱动最小集合

判据只有一条：**ExitBootServices 之后，机器还能不能干活。**

### 必需（缺了就等于没接手）

| # | 驱动 | 为什么必需 | 现状 |
|---|------|-----------|------|
| 1 | **块设备**：NVMe 或 AHCI | 没有它就没有文件系统，dir/type/跑程序全没 | NVMe ✓ AHCI ✓（真机待查） |
| 2 | **输入**：PS/2 或 USB HID | 没有它就没有命令行 | PS/2 ✓ USB HID ✗ |
| 3 | 显示 | 内核直接用固件给的 GOP 句柄，**不需要驱动** | ✓（不需驱动） |

**这两条是"最小集合"的全部。** 其余都可以没有，机器仍然是一台能用的 DOS。

### 值得有（提升，不是生存）

| # | 驱动 | 说明 |
|---|------|------|
| 4 | 另一类块设备 | 一台机器只需要一个能读盘的；写上两个是为了换机器不用改配置 |
| 5 | 鼠标 | 有 PS/2 的 aux 口，代码已经在，还没接进输入后端 |
| 6 | RTC | 时间戳。可以后补 |

### 明确不需要（这个阶段）

声卡 / 网卡 / 蓝牙 / 摄像头 / 雷电 —— 一个都不在"让机器跑起来"的路径上。

## 四 VMD 到底要不要弄

**要，但优先级排在"块设备能认出盘"之后**，而且它有三种情况，量级完全不同：

```
A  直通模式（单盘）
   VMD 只做总线隐藏，盘还是标准 NVMe
   -> 扫 VMCAP 给的总线范围就能找到，我们的代码已经能这么干
   -> 工作量：小

B  RST RAID 卷（多盘阵列）
   盘不在 NVMe 层，命名空间被 RAID 元数据藏着
   -> 需要解析 Intel RST 的卷格式，那是**另一条产品线**的工作量
   -> 工作量：大，且要真机样本才能验证

C  在 BIOS 里把 RST 改成 AHCI/NVMe
   最简单，但那是让用户改机器，不是我们解决问题
```

**结论**：VMD 的**探测器**（发现 class 0x0104、读 VMCAP、扫那一段）保留 —— 它便宜且正确。
**VMD 的 RAID 卷解析**等真的遇到用户机器是这种情况再做，不要提前造。
