# 驱动 SDK —— 接口设计（草案）

> 状态：**设计阶段，没有代码。**
> 先把接口定下来，再谈实现 —— 标准先行，代码才好写。

---

## 0. 先说现状（侦察结论）

```
驱动         是一个 **EFI 应用**（PE），由 drv.c 用固件的 LoadImage + StartImage 拉起来
驱动运行时   repos/TNDOS-SDK/lib/drvlib.c —— **只有 23 行**，全是输出助手
             而它们写的是 EFI_SYSTEM_TABLE->ConOut
内核侧       TND_DRIVER 只是一个**记账结构**（路径、状态、次数）
tnd.h        **没有任何驱动协议类型**
```

**结论：驱动是固件的驱动，不是 TNDDOS 的。**

```
内核把驱动拉起来 -> **然后就不管了**
驱动自己去找固件要 GOP / SimpleTextInput / ...
-> **内核与驱动之间没有接口** ✗
```

**这就是「驱动 SDK 很麻烦」的真正原因** —— 它不是写文档，是**从零定义一层协议**。

---

## 1. 要定义的四件事

```
1  驱动怎么被加载      现在：固件 LoadImage(PE)   目标：内核自己加载 TNX
2  驱动怎么登记自己    现在：没有                 目标：一个明确的入口
3  内核怎么调用驱动    现在：没有                 目标：一套设备接口
4  驱动怎么拿到设备    现在：直接问固件           目标：问内核，或者内核分配
```

**第 3、4 条是核心。** 1、2 条只是把加载路径换掉。

---

## 2. 一个关键取舍：**中断**

现在没有 IDT。所以接口里中断占什么位置，直接决定能不能现在开工：

```
a  接口里没有中断（纯轮询）
   -> 现在就能做 / 简单
   -> 但键盘轮询真的很难受，而且不是长久之计 ✗

b  接口里**留中断的位置，先不实现**
   -> 现在就能做 /
   -> 将来接中断**不用改接口** ✓✓✓

c  接口依赖中断
   -> 必须先做 IDT ✗ 卡住
```

**选 b。** 这和 TNX 的 `SIGN` 段是同一个手法：

> **留位置，不实现。** 位置先占住，实现等需求。

**具体做法**：驱动结构里留中断相关的槽位，但内核侧先只支持「轮询」这一种模式；
驱动可以声明「我希望有中断」，内核如实回答「暂时没有」，驱动退化成轮询。

**驱动必须能接受「没有中断」这个答案** —— 否则它就不是可移植的。

## 3. 驱动长什么样（草案）

### 3.1 加载

```
驱动 = **TNX 文件**，不再走固件 LoadImage
      -> 这是「能不能离开 UEFI」的地基之一
```

**但驱动和普通程序需要区分。** 两种做法：

```
a  用 TNX 的 Flags 位标一个「我是驱动」      -> 要改 TNX 规范 ✗
b  驱动就是一个普通 TNX，**靠它的入口说明自己** -> 不改格式
```

**倾向 b**：包管理器那次的教训 —— **能用魔数或入口解决的事，不要动格式。**

### 3.2 登记

驱动启动后，向内核登记自己：

```
驱动入口   drv_main(api) 之类，和 tnx_main 并列
登记调用   内核给它一个「驱动表」，驱动填进去
```

**填什么？** 最少要有：

```
名字          给人和日志看
类型          显示 / 输入 / 块设备 / ...
probe         内核问它「这个设备你要不要」
attach        要了之后初始化
read / write  数据面
```

**注意 probe / attach 这个形状** —— 它和 UEFI 的驱动模型是同一套思路，
不是巧合：**那套思路是对的**，只是我们不用 UEFI 的实现。

### 3.3 设备从哪来

```
现在   驱动自己去找固件（GOP / SimpleTextInput）
目标   内核把设备描述交给驱动
```

**但设备从哪来？** 这是最深的一层：

```
短期   仍然从固件拿（GOP / 块设备句柄），内核转手给驱动
长期   内核自己枚举 PCI（0xCF8/0xCFC），不再问固件
```

**短期做法能让 SDK 现在就有用**，长期做法才是「脱离 UEFI」的那一步。

## 5. 不做什么

```
NO  驱动的动态加载 / 卸载      一次一个程序，DOS 语义
NO  驱动间依赖                 和 TNP 同理：记录可以，求解不做
NO  设备树 / 复杂拓扑          用最简单的设备描述
NO  电源管理
NO  热插拔                     以后再说
```

## 6. 和 IDT 的关系（说清楚）

```
之前说的是「驱动 SDK 先，IDT 后」
现在看清了：**先定接口，接口里中断的位置定了，才知道 IDT 什么时候必须做**

按第 2 节选 b -> **IDT 可以更晚**，因为接口不依赖它
```

**接口留了位置，顺序就自由了。** 这就是「留位置不实现」的收益。
